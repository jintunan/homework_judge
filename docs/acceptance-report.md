1. 复制 `.env.example` 为 `.env`，填写 `DASHSCOPE_API_KEY`。
2. 执行 `pnpm start`。
3. 浏览器打开 `http://127.0.0.1:8787`。
4. 上传试卷与答案，等待处理后进入人工复核页。

## 2026-08-08 增量验收：派生填空配置与正式批改状态一致性

### 根因与修复结果

- 截图中的报错不是多空识别再次失败，而是此前 GET 只在界面返回 `source=derived` 预览，没有把配置头和逐空记录写入数据库；当前复现任务的第 9—12 题虽已确认，但 `config_version` 为空且正式空位数为 0，因此评分输入仍按数据库正式状态抛出 `FILL_BLANK_CONFIG_REQUIRED`。
- GET 继续保持只读，并新增 `autoConfirmable` 与 `blockingReasons`，明确区分“可以安全自动确认”和“必须逐空检查保存”。
- 新增统一的填空配置确认服务。确认题目、完成任务、开始批改三个正式动作会用确定性规则准备整批候选，在同一数据库事务中保存配置头、全部空位和审计事件；任一题存在 blocker 时整批零写入。
- 复合区域共享、区域缺失和区域数量冲突仅作为 advisory warning；标准答案缺失、答案无法安全拆分、题目/空位分值无效或分值不守恒会阻止自动确认。
- 已有教师保存配置始终优先，重复触发只返回 existing，不增加配置版本、空位或自动确认审计；存在“配置头有而空位缺失”的异常历史状态时返回 `saved_config_inconsistent`，不会覆盖异常数据。
- 历史已完成任务在创建评分运行前执行兼容补齐，因此当前第 9—12 题在下次点击“开始批改”时会生成 4 个配置头和 11 个空位，再进入原评分输入流程，不再触发截图中的通用报错。

## 2026-08-10 增量验收：题框驱动的通用逐空识别与模型批改

### 已实现

- 完整题框改为模板侧版本事实：模型只生成草稿，教师逐题编辑/确认并冻结；全部有效题未完成前，学生上传和处理同时关闭。
- 填空配置改为不可变版本：只读预览不落库，任意 `n` 使用连续 B1...Bn；空位、独立锚点、逐空答案和显式逐空分值不一致时失败关闭，不再静默均分。
- 学生侧只做页面配准和冻结题框集批量映射；缺页、低质量、裁切、越界、退化或冲突进入 `mapping_needs_review`，答案模型零调用。
- 第一阶段为无标准答案的严格键控转写；模型返回必须精确覆盖运行时键集合，不能按换行、区域顺序或整题摘要补齐。
- 第二阶段逐空调用模型判定，后端按冻结 Decimal 分值确定性汇总；教师可只修正一个键，兄弟空保持不变并留审计。
