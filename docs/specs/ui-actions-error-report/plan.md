# 前端操作闭环与复核后错题报告 Plan

## 架构概览

本次采用增量修复，不更换现有 React、TanStack Query、FastAPI、SQLite 和进程内任务管理器。前端在现有页面内统一异步操作的忙碌、成功、失败与禁用原因；后端把“复核状态提交”和“生成物任务调度”作为可验证的连续流程，并继续使用结果修订号保证报告版本正确。

前端仍以服务端状态为事实来源。按钮触发请求后先进入本地忙碌状态，成功后按稳定查询前缀刷新运行、题目、复核项和生成物；当运行处于处理中时持续轮询，直到 `completed` 或可恢复的 `failed`。页面不通过猜测或固定延时宣布报告已经完成。

后端继续由教师复核服务完成分项重算和审计，由批改 API 在最后一个复核项关闭后通过任务管理器启动生成物流程。生成物服务先生成批注试卷，再生成错题报告，并以 `(grading_run_id, artifact_type, result_revision)` 保持幂等。服务中断时沿用现有启动中断标记，将运行转为可恢复失败，教师可只重试生成阶段。

## 核心数据结构与接口

### ActionState

前端页面级操作状态，保留在各页面或小型复用组件中：

- `busy`：操作正在进行，禁用重复提交。
- `message`：成功或进度说明，使用状态语义展示。
- `error`：可读失败原因，使用警告语义展示。
- `disabledReason`：按钮不可用时的具体前置条件说明。

不引入全局消息中心；操作反馈放在触发区域附近，避免多个页面共享状态造成旧消息残留。

### GradingReviewResolutionResult

扩充前端对现有复核响应的类型声明，与后端当前返回值对齐：

- `reviewItemId`
- `gradingRunId`
- `questionResultId`
- `status`
- `score`
- `remainingReasons`

前端使用 `remainingReasons` 和重新获取的运行详情决定显示“仍需复核”或“正在生成”，不在客户端自行计算最终状态。

### GradingRun

继续使用现有运行字段作为生成流程状态机：

- `status` / `stage`：`needs_review → generating_annotation → generating_report → completed`，失败时为 `failed`。
- `openReviewCount`：为零才允许生成结果文件。
- `resultRevision`：所有当前生成物必须与该修订一致。
- `retryable`、`errorCode`、`errorMessage`：控制恢复入口和失败说明。

### GradingArtifact

继续使用现有生成物记录：

- `type`：`annotation` 或 `error_report`。
- `status`：`current` 或 `stale`。
- `resultRevision`：与运行当前修订对应。
- `previewUrl` / `downloadUrl`：只对当前生成物开放。

前端只将 `current` 的错题报告作为正式预览和下载入口；过期版本可保留历史但不作为当前结果。

### 现有 HTTP 接口

- `POST /grading-review-items/{id}/resolve`：保存一次复核结果；关闭最后一项时调度生成物任务。
- `GET /grading-runs/{id}`：获取运行阶段、剩余复核数和失败信息。
- `GET /grading-runs/{id}/questions`：刷新题目得分与状态。
- `GET /grading-runs/{id}/review-items`：刷新剩余复核项。
- `GET /grading-runs/{id}/artifacts`：获取当前及过期生成物。
- `POST /grading-runs/{id}/retry`：根据保存阶段恢复；生成物失败时只执行生成流程。
- `POST /grading-runs/{id}/regenerate`：最终结果修订后显式重生当前生成物。
- `GET /grading-artifacts/{id}/preview` 与 `/download`：返回当前 PDF；过期或非法生成物保持拒绝。

本次优先修正接口调用和响应契约，不新增功能重复的端点。

## 模块设计

### 操作反馈组件

**职责：** 提供一致的状态/错误文字、`role="status"` / `role="alert"` 语义和禁用原因展示。

**对外接口：** 接收成功消息、错误消息和可选禁用原因；不负责发请求或管理业务状态。

**依赖：** React 与现有样式系统。

### API 客户端

**职责：** 保持统一错误解析，补齐复核返回类型，并为预览/下载操作提供可检测失败的调用方式。浏览器直接打开 PDF 前先验证当前生成物可用，失败时把服务端错误返回页面。

**对外接口：** 现有 `api`、上传和复核辅助函数；必要时增加生成物打开/下载辅助函数。

**依赖：** 共享契约与响应 envelope schema。

### 任务列表、新建与识别进度页面

**职责：** 审计新建、删除、上传、重试、导航等操作；补齐忙碌文字、异常捕获和失败后的状态恢复。无数据、请求失败和禁用前置条件均可见。

**依赖：** API 客户端、React Query、路由。

### 题目复核页面

**职责：** 为保存、确认、取消确认、标记无关和完成任务补齐独立忙碌与错误反馈；完成按钮旁显示所有阻塞原因；每次操作后刷新题目、确认数和孤立答案。

**依赖：** 现有题目/答案接口、React Query。

### 学生答卷页面

**职责：** 为上传、补算题框、重新处理、学生切换和翻页提供清晰状态；“进入批改工作台”不可用时显示答卷或题框尚未就绪的原因。

**依赖：** 学生提交接口、React Query、路由。

### 批改工作台

**职责：** 统一开始、继续、复核、调整错误位置、重新生成、筛选、翻页、预览和下载反馈。复核成功后使用稳定查询键刷新全部相关数据；有剩余项时自动选择下一道待复核题，最后一项完成时保持轮询直到报告成为当前生成物或运行失败。

**依赖：** API 客户端、共享批改契约、React Query、生成物接口。

### 教师复核服务

**职责：** 保持现有分项重算、依赖传播、题级审计、运行总分更新和旧生成物失效逻辑。确保只有审计通过的结果可以关闭复核项，最后一项关闭后运行状态原子地进入 `generating_annotation`。

**依赖：** SQLite 事务、评分审计、生成物版本字段。

### 批改 API 与任务调度

**职责：** 在复核事务完成后重新读取运行状态；当进入 `generating_annotation` 时，以 `grading-artifacts:{runId}` 作为任务键启动生成物。重复请求由复核项状态和任务键共同拦截。启动失败必须转成可见错误，不能返回成功后静默停留。

**依赖：** 教师复核服务、任务管理器、批改流水线。

### 生成物服务

**职责：** 校验无开放复核项、所有题目最终化且非满分题具有真实错误位置；依次生成批注和错题报告；保存当前修订生成物并最终完成运行。异常时只将生成阶段标记为可恢复失败，不回滚教师复核和分数。

**依赖：** 最终评分结果、学生作答区域、PDF 渲染、生成物表。

## 模块交互

```text
教师点击复核确认
  → 前端禁用重复提交并调用复核接口
  → 教师复核服务重算、审计、提交复核事务
  → 若仍有复核项：运行保持 needs_review
  → 若已无复核项：运行进入 generating_annotation
  → API 以运行 ID 启动唯一生成任务
  → 生成批注试卷并记录当前修订
  → 生成错题报告并记录相同修订
  → 运行进入 completed
  → 前端轮询刷新运行与生成物
  → 显示可预览、可下载的当前错题报告
```

错误分支：

```text
请求校验失败
  → 前端解除忙碌并就地显示可读原因

生成物失败或服务中断
  → 运行进入 retryable failed
  → 前端显示生成失败原因与“继续生成”
  → 重试接口只恢复 generate_artifacts
  → 已确认复核项、最终分数和原始答卷不变
```

## 技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 修复范围 | 全主要页面按钮审计 + 报告端到端闭环 | 直接覆盖用户报告的两类问题，避免只修一个按钮 |
| 前端状态来源 | 服务端运行状态 + React Query 轮询 | 报告生成是后台任务，客户端不应凭时间猜测完成 |
| 反馈位置 | 操作附近的页面级状态/错误提示 | 教师能立即知道哪个动作成功或失败，且不引入全局旧消息 |
| 查询刷新 | 稳定查询前缀失效，不把时间戳作为唯一刷新触发 | 保证复核后题目、运行、复核项与生成物同步更新 |
| 最后复核调度 | 事务提交后由 API 使用唯一任务键启动 | 避免事务内启动任务，并防止重复生成 |
| 报告幂等 | 运行 ID + 类型 + 结果修订号 | 沿用现有唯一语义，重复触发不产生多个当前版本 |
| 生成失败恢复 | 标记可恢复失败，只重试生成物 | 保护教师已确认结果，减少不必要的重新评分 |
| 缺失错误位置 | 阻止最终生成并明确提示教师处理 | 不伪造证据，符合已批准 spec 的边界 |
| PDF 操作 | 验证当前生成物后再预览/下载并捕获错误 | 避免链接点击后浏览器静默失败 |
| 测试策略 | 组件交互 + API 集成 + 真实浏览器主流程 | 同时覆盖按钮表象、后端状态机和最终可用文件 |
