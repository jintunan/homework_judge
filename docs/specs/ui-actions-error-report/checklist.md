# 前端操作闭环与复核后错题报告 Checklist

> 每项都通过运行测试或观察实际行为验证；先记录证据，再判断通过与否。

## 实现完整性

- [ ] 任务列表、新建任务、识别进度、题目复核、学生答卷和批改工作台的所有按钮及按钮式链接均已列入审计清单。（验证：搜索全部 `<button>`、按钮式 `<Link>` 和生成物 `<a>`，逐项对照；对应 AC1）
- [ ] 每个可用按钮都会产生导航、本地状态变化或服务端请求，并显示可观察结果。（验证：逐页点击审计清单；对应 AC1）
- [ ] 所有异步按钮执行期间显示忙碌文字或进度，且不能重复提交。（验证：延迟请求并连续点击；对应 AC2、AC9）
- [ ] 所有异步按钮成功后刷新受影响的数据并清除旧错误。（验证：模拟成功响应并观察页面无需整页刷新；对应 AC2）
- [ ] 所有异步按钮在服务端校验失败和网络失败后解除忙碌、显示可读错误并允许重试。（验证：分别返回 4xx envelope 和拒绝 fetch；对应 AC2）
- [ ] 反馈消息使用状态或警告语义，文字表达不只依赖颜色。（验证：Testing Library 查询 `status`/`alert` 并进行灰度检查；对应 AC8）

## 禁用原因与前置条件

- [ ] 新建任务缺少试卷或参考答案时，页面指出具体缺少的文件。（验证：分别只选择一个文件后提交；对应 AC3）
- [ ] 题目复核“完成任务”不可用时，页面分别说明未确认题目和未处理孤立答案数量。（验证：构造两类阻塞数据；对应 AC3）
- [ ] 学生答卷未处理完成或题框未就绪时，页面说明不能进入批改工作台的原因。（验证：构造 uploaded、processing、needs_review 状态；对应 AC3）
- [ ] 批改开始、错误位置调整、继续生成等入口不可用时，页面说明缺少的状态或证据。（验证：构造答卷未就绪、当前页无证据、运行不可重试状态；对应 AC3）
- [ ] 前置条件满足后，按钮无需刷新整页即可恢复可用。（验证：通过查询刷新改变条件并观察按钮；对应 AC3）

## 任务与识别页面操作

- [ ] 删除任务点击后只打开确认对话框，不触发任务卡导航。（验证：点击删除并断言当前 URL 不变）
- [ ] 删除取消、成功和失败分别关闭对话框、刷新列表或显示错误。（验证：三种 UI 测试）
- [ ] 上传任务成功后只导航一次，失败后保留已选文件并可重试。（验证：延迟成功与失败请求）
- [ ] 识别处理重试成功后刷新进度，失败后显示错误且按钮恢复。（验证：ProcessingPage UI 测试）
- [ ] 识别完成后的路由跳转由副作用执行，不产生渲染阶段更新警告。（验证：测试控制台无 React 警告）

## 题目复核页面操作

- [ ] 保存修改、确认本题和取消确认均有独立忙碌状态、成功反馈和失败反馈。（验证：逐操作模拟成功与失败；对应 AC1、AC2）
- [ ] 同一题的保存和确认不能在请求进行中重复触发或相互覆盖。（验证：挂起请求并连续点击；对应 AC9）
- [ ] “标记无关”失败时显示错误，成功后孤立答案数量和完成准入立即更新。（验证：ReviewPage UI 测试）
- [ ] 全部题目确认且孤立答案清理后，“完成任务”恢复可用并只提交一次。（验证：逐步满足条件并连续点击；对应 AC3、AC9）
- [ ] 切换题目后不会显示上一题遗留的临时成功或失败消息。（验证：操作后切换题目）

## 学生答卷页面操作

- [ ] 上传学生答卷、补算题目区域和重新处理均显示执行中、成功和失败结果。（验证：三个 mutation 的 UI 测试；对应 AC1、AC2）
- [ ] 自动补算请求失败不会被静默吞掉，并保留手动重试入口。（验证：首次自动请求失败）
- [ ] 学生切换和翻页只改变所选数据，不会误发上传、补算或重试请求。（验证：请求调用计数）

## 教师复核状态转换

- [ ] 解决一个非最后复核项后，题目得分、剩余复核数量和当前题状态立即更新，运行保持 `needs_review`。（验证：UI 测试 + API 集成测试；对应 AC4）
- [ ] 存在下一道待复核题时，界面自动定位该题或明确显示剩余项。（验证：两道待复核题场景；对应 AC4）
- [ ] 解决最后一项后，运行原子地从 `needs_review` 进入 `generating_annotation`，没有开放复核项。（验证：数据库事务与 API 状态断言；对应 AC4）
- [ ] 最后一项复核解决后自动启动生成任务，无需教师再点击“重新生成文件”。（验证：任务管理器启动调用与端到端状态序列；对应 AC4）
- [ ] 同一复核项重复提交返回冲突，不会二次改变题目得分、总分或结果修订。（验证：重复 POST 并比较数据库；对应 AC9）
- [ ] 同一运行的重复生成调度只存在一个有效任务和一套当前生成物。（验证：相同任务键并发请求与生成物计数；对应 AC9）

## 错题报告生成与内容

- [ ] 运行依次经过 `generating_annotation`、`generating_report` 和 `completed`。（验证：轮询运行状态并记录序列；对应 AC4）
- [ ] 完成状态下同时存在当前批注试卷和当前错题报告，且二者 `result_revision` 与运行一致。（验证：生成物查询；对应 AC5）
- [ ] 每道非满分题在报告中包含题号、题型、得分/满分、真实错误裁剪、错误原因、知识点和简短建议。（验证：报告 JSON/预览数据及渲染 PDF；对应 AC5）
- [ ] 满分题不进入逐题错题列表，但总分和正确题汇总保持正确。（验证：混合正误夹具；对应 AC5）
- [ ] 报告得分、错误原因和错误位置与最终题目结果及证据一致。（验证：跨表、预览数据和 PDF 内容对比；对应 AC5）
- [ ] 缺少可靠错误位置的非满分题不能生成猜测性报告，并向教师显示可操作原因。（验证：清空错误位置后生成；对应 AC5）
- [ ] “预览错题报告”和“下载错题报告”返回有效 PDF，文件以 `%PDF` 开头。（验证：HTTP 响应和浏览器打开；对应 AC5）
- [ ] 报告完成后入口无需整页刷新即可出现。（验证：UI 轮询状态序列；对应 AC5）
- [ ] 预览、下载遇到过期 409 或网络错误时留在当前页并显示错误。（验证：UI 测试；对应 AC2、AC7）

## 生成失败与恢复

- [ ] 模拟批注或报告生成失败后，运行进入 `failed`、`retryable=true`，并保存可读错误码和错误消息。（验证：故障注入；对应 AC6）
- [ ] 生成失败后界面显示失败阶段、原因和“继续生成”入口。（验证：GradingWorkspacePage UI 测试；对应 AC6）
- [ ] 点击继续处理只执行生成物阶段，不重新识别或评分。（验证：比较模型/评分调用计数；对应 AC6）
- [ ] 重试前后教师复核记录、题目最终分数、总分和原始学生答卷摘要完全一致。（验证：数据库快照与 SHA-256；对应 AC6、AC10）
- [ ] 重试成功后产生当前批注和错题报告并进入 `completed`。（验证：失败恢复集成测试；对应 AC6）
- [ ] 服务在生成阶段中断并重启后，运行被标记为可恢复失败而不是永久停在“生成中”。（验证：进程中断/启动状态测试；对应 AC6）

## 修订与过期生成物

- [ ] 修改已完成运行的最终判定或错误位置后，旧批注和报告立即标记为 `stale`。（验证：更新接口后查询生成物；对应 AC7）
- [ ] 过期报告的预览和下载接口返回 409，前端不把它显示为当前报告。（验证：API 与 UI 测试；对应 AC7）
- [ ] 重新生成后的报告使用新的 `result_revision`，并与新批注修订一致。（验证：生成物记录对比；对应 AC7）
- [ ] 历史生成物记录仍保留，不被新版本覆盖或删除。（验证：查询所有版本；对应 AC10）

## 集成与架构约束

- [ ] 前端以服务端运行状态为事实来源，不使用固定延时直接宣告报告完成。（验证：代码检查和延迟状态测试）
- [ ] 复核事务提交后才启动生成任务，生成任务不在数据库事务内执行。（验证：调用顺序测试）
- [ ] 生成物服务只读取最终评分结果，不修改题目得分或评分细则。（验证：生成前后评分表摘要；对应 AC10）
- [ ] 原始学生答卷文件在复核、生成和重试前后摘要不变。（验证：SHA-256；对应 AC10）
- [ ] 历史批改运行、教师决策和评分规则仍可读取且内容不变。（验证：旧数据库/运行回归；对应 AC10）

- [ ] TypeScript 类型检查通过。（验证：`pnpm typecheck`；对应 AC10）
- [ ] 全部前端 UI 测试通过，且无未处理 Promise 或 React 更新警告。（验证：`pnpm test:ui`；对应 AC1-AC3、AC8）
- [ ] 全部后端单元与集成测试通过。（验证：`pnpm test:python`；对应 AC4-AC7、AC9-AC10）
- [ ] Ruff 与 mypy 检查通过。（验证：`pnpm lint`；对应 AC10）
- [ ] 生产构建和 Python 编译检查通过。（验证：`pnpm build`；对应 AC10）

## 端到端场景

- [ ] 场景 A：进入有多个待复核项的批改工作台 → 解决一个复核项 → 得分与剩余数量更新 → 自动定位下一项。（验证：真实浏览器；对应 AC4）
- [ ] 场景 B：解决最后一项复核 → 自动显示生成批注 → 生成报告 → 完成 → 出现预览和下载入口。（验证：真实浏览器 + API 状态记录；对应 AC4、AC5）
- [ ] 场景 C：报告生成失败 → 页面显示原因 → 点击继续生成 → 不重新评分 → 报告成功可下载。（验证：故障注入浏览器场景；对应 AC6）
- [ ] 场景 D：完成后修改错误位置 → 旧报告失效 → 重新生成 → 新报告反映最新错误位置。（验证：真实浏览器与 PDF 对比；对应 AC7）
- [ ] 场景 E：快速重复点击确认和生成按钮 → 仅一次有效提交、分数不重复变化、只有一份当前报告。（验证：请求与数据库计数；对应 AC9）

- [ ] Chrome 在 1280×720 下可用鼠标走完整个复核与报告流程，所有主按钮可见且未被遮挡。（验证：截图与交互记录；对应 AC8）
- [ ] Edge 在 1280×720 下可用鼠标走完整个复核与报告流程，所有主按钮可见且未被遮挡。（验证：截图与交互记录；对应 AC8）
- [ ] 仅使用键盘可以进入批改工作台、选择待复核题、提交复核、预览和下载报告。（验证：Tab、Enter、Space 操作记录；对应 AC8）
- [ ] 页面无 Vite 错误遮罩、空白区域、阻断性横向溢出或控制台未处理错误。（验证：浏览器截图、DOM 和控制台检查；对应 AC8）
