## D. 计算题四种执行路径

### D1. 单次成功 `single_pass`

- [x] 单批次计算题发生 1 次快速模型调用。
- [x] 旧定位调用次数为 0。
- [x] 旧转写调用次数为 0。
- [x] 定位区域、对应转写、证据引用和最终分段正确保存。
- [x] 整题与批次路径均记录为 `single_pass`。

**对应验收标准**：AC4。

### D2. 复用定位后转写回退 `transcription_fallback`

- [x] 快速定位结构有效，但转写缺失、空文本不可用、重复或映射错误时进入该路径。
- [x] 旧定位调用次数为 0，不重复定位。
- [x] 只把未解决的已验证定位区域交给兼容转写。
- [x] 每道计算题兼容转写调用最多 1 次。
- [x] 快速成功区域不会在兼容转写中重复请求。
- [x] 整题或对应批次记录 `transcription_fallback`。

**对应验收标准**：AC5。

### D3. 完整回退 `full_fallback`

- [x] 快速请求最终失败时，对对应批次调用旧定位。
- [x] 快速定位 JSON 或定位结构无效时，对对应批次调用旧定位。
- [x] 旧定位得到的有效正向区域进入兼容转写。
- [x] 旧定位或转写再次失败时不会无限重试，并进入现有 `needs_review`。
- [x] 多批次题目只重新定位失败批次，不重复处理成功批次。
- [x] 任一批次执行旧定位时，整题路径记录为 `full_fallback`。

**对应验收标准**：AC6。

### D4. 可靠空白 `reliable_blank`

- [x] 快速结果可靠判定所有窗口为空白时，不调用兼容转写。
- [x] 保存现有 `blank_search_window` 空白证据。
- [x] 最终识别文本为空，`isBlank` 与现有可靠空白规则一致。
- [x] 整题路径记录为 `reliable_blank`。
- [x] 低置信度空白不会被误标为可靠空白，仍进入人工复核。
