# 学生答卷识别并发与计算题单次识别技术计划

## 1. 实现范围

本次只调整学生答卷的题目识别调度，以及计算题的定位、转写和回退编排。页面渲染、页面配准、题框版本、逐空配置、评分规则、数据库表结构、前端页面和历史版本协议均不修改。

实现必须继续使用现有 `StudentPipeline` 原子提交边界：所有题目识别完成并通过提交前校验后，才把本次处理修订提升为当前正式版本。

## 2. 总体设计

### 2.1 单份答卷最多 3 题并行

在 `StudentPipeline._recognize_responses` 中把单题处理抽成无共享可变结果的异步工作单元，并为每份答卷建立一个容量为 `student_recognition_concurrency` 的信号量。

- 新增 `STUDENT_RECOGNITION_CONCURRENCY` 配置，默认值和允许的最大值均为 3，允许显式调低到 1 或 2。
- 选择题、填空题、计算题共享该信号量；一个计算题从开始规划到快速路径或回退结束始终占用一个题目槽位。
- 同一道计算题的多个页面批次仍按顺序执行，避免一个复杂题目瞬间占用全部远程请求额度。
- 为所有有效题目按原始顺序创建任务；收集结果时使用输入顺序，不使用完成顺序，因此保存顺序不变。
- 收集阶段完整排空所有任务结果，再按原始题目顺序抛出第一个异常。这样不会遗留后台请求，也维持“本次修订整体失败、不提交部分结果”的语义。
- 外层任务被取消时，显式取消并等待全部子任务结束，防止处理修订已失败后仍有模型请求继续运行。

题目并发只控制单份答卷。所有模型请求仍经过 `DashScopeClient` 的全局信号量，因此实际模型并发为全局限制与当前工作负载共同决定的更小值。

### 2.2 计算题单次定位并转写协议

新增独立于旧定位协议的快速协议版本，例如 `calculation-localize-transcribe-v1`。旧 `calculation-answer-localization-v1` 保留，专门用于完整回退，避免为快速路径改变现有兼容行为。

快速协议仍以每个既有计算题搜索片段的“空白模板图 + 对齐后的学生图”为输入。每个窗口继续返回：

- `fragmentKey`
- `status`：`located`、`blank` 或 `uncertain`
- 窗口置信度和问题信息
- 定位区域列表

每个 `located` 区域在原有 `bbox`、定位置信度和定位问题之外，同时返回：

- `transcription`
- `transcriptionConfidence`
- `transcriptionIssues`

模型只负责忠实转写学生新增内容，不解题、不评分、不接触参考答案。可靠空白窗口没有区域，也不要求伪造转写字段。

### 2.3 两层校验与本地证据绑定

快速结果分成两个相互独立的校验层，保证能够准确选择回退范围。

1. 定位层先从快速输出中投影旧定位字段，复用现有定位标准化器验证 JSON 结构、片段归属、窗口状态、区域边界、批次和尝试标识。
2. 转写层再验证每个最终保留的定位区域恰好有一份转写，并以 `(fragmentKey, modelCandidateIndex)` 与区域绑定；禁止缺失、重复或越界映射。
3. 证据 ID、模板页 ID、学生页 ID、配准修订 ID 和原图坐标全部由本地现有证据生成逻辑产生，绝不接受模型自报的证据 ID。
4. 只有映射成功的转写才会附着到对应本地证据并进入最终 `segments`。最终文本始终按证据 `sort_order` 合并。

新增的标准化结果需要分别暴露 `localization_contract_valid` 与 `transcription_contract_valid`。低置信度和模型声明的不确定性会产生问题并进入 `needs_review`，但只要结构和映射有效，就不为了低置信度额外回退；这与现有人工复核门槛一致，也能保留请求节省。

### 2.4 回退状态机

每个计算题批次先尝试快速调用，之后按以下规则处理：

```text
快速调用
  ├─ 请求失败或定位结构无效 → 旧定位调用 → 待补转写区域
  ├─ 定位有效、转写结构/映射无效 → 复用定位 → 待补转写区域
  ├─ 定位与转写均有效 → 直接使用
  └─ 可靠空白 → 保存空白证据，不转写

全部批次定位完成
  └─ 将所有“待补转写区域”合并为一次旧转写调用
```

这样，多批次题目中已经成功的快速转写不会重复请求；定位有效但转写失败的批次不会重新定位；需要完整回退的批次只重做自己的定位。每道计算题最多追加一次兼容转写调用，仍服从现有超时、重试和全局模型并发限制。

路径标识按以下优先级生成：

1. 任一批次重做旧定位：`full_fallback`
2. 未重做定位但任一区域使用旧转写：`transcription_fallback`
3. 整题为可靠空白：`reliable_blank`
4. 其余全部由快速协议完成：`single_pass`

每个批次另存自己的路径，支持跨页题目的混合路径追踪。

### 2.5 快照兼容与用量统计

现有 `raw_recognition.localization.schemaVersion` 保持为 `1`，避免破坏自动评分和提交前证据校验。所有新信息采用增量字段：

- 整题 `recognitionPath`
- 批次 `recognitionPath`
- 快速协议版本、原始输出、使用量和错误
- 旧定位回退的协议版本、原始输出、使用量和错误
- 兼容转写的原始输出、使用量和错误

原有 `plan`、`batches`、`evidence`、`issues`、`evidenceComplete`、`reliableBlank`、`segments` 和证据几何字段继续保留。`raw_recognition.usage` 汇总快速调用与所有回退调用，批次快照同时保留各自使用量，便于计算请求数和成本。

增加不含学生答案正文的结构化运行日志，记录题目类型、耗时、计算题路径、批次数、快速请求数和回退请求数，用于后续定位真实环境瓶颈。

### 2.6 配置生效

- `STUDENT_RECOGNITION_CONCURRENCY=3`：单份答卷题目级上限，代码层强制不超过 3。
- `MODEL_CONCURRENCY` 默认值与示例值由 2 调整为 3，使默认部署能够真正同时发出 3 个模型请求。
- 当前本地 `.env` 的 `MODEL_CONCURRENCY=2` 需要同步改为 3；只修改这一项，不触碰 API 密钥等配置。
- 若部署方显式把 `MODEL_CONCURRENCY` 配成 1 或 2，系统继续服从更小的全局上限。

## 4. 详细处理顺序

1. 加载题目、题框版本、逐空配置和页面配准结果，保持现状。
2. 构造题目工作单元并以每份答卷最多 3 个并发执行。
3. 普通题型继续调用现有识别方法；填空题继续使用逐空配置和现有严格协议。
4. 计算题生成现有搜索计划，逐批尝试快速协议。
5. 对每批输出先验证定位，再验证区域转写映射，并记录该批路径。
6. 仅对快速转写不可用或旧定位回退产生的区域，统一调用一次旧转写方法。
7. 生成本地证据、按证据顺序合并转写和空白段，计算置信度及 `needs_review`。
8. 按原试卷顺序汇总全部题目结果。
9. 继续执行现有提交前证据一致性校验和事务/CAS 提交；任一不可恢复异常时不提升本次修订。

## 5. 测试计划

### 5.1 题目并发

- 6 道带可控屏障的模拟题同时运行，确认峰值恰为 3 且从不超过 3。
- 人为让第 4、2、1 题依次先完成，确认返回和最终保存仍按原题目顺序。
- 其中一道抛出异常，确认所有任务被排空或取消，没有悬挂调用，且没有部分正式结果。
- `STUDENT_RECOGNITION_CONCURRENCY=3` 且全局模型并发分别为 1、2、3 时，确认实际模型请求峰值分别不超过 1、2、3。

### 5.2 计算题快速协议

- 完整定位和转写：一个单批次计算题只调用一次快速服务，不调用旧定位和旧转写。
- 可靠空白：只调用一次快速服务，保存空白窗口证据，不调用旧转写。
- 定位有效、转写缺失或映射错误：不调用旧定位，只对未解决区域调用一次旧转写。
- 快速请求异常、无效 JSON、未知片段、非法区域：调用一次旧定位，并对旧定位得到的区域调用一次旧转写。
- 低置信度但结构完整：不触发回退，结果进入 `needs_review`。
- 多批次混合：成功批次保留快速转写，失败批次局部回退，最终证据和分段顺序正确，整题路径按优先级记录。
- 回退转写再次失败：不无限重试，保留定位证据并进入 `needs_review`。

### 5.3 兼容与性能

- 现有计算题定位、可靠空白、跨页、边界裁剪、配准低置信度、处理修订和评分重放测试全部继续通过。
- 用 15 题、每次模型调用固定延迟的模拟模型对比串行基线，断言墙钟时间显著下降。
- 3 道单批次计算题均成功走快速路径时，断言总模型请求比旧流程减少 3 次。
- 完整运行后端单元测试与相关集成测试；若仓库全量测试耗时可接受，再执行全量测试。

## 7. 风险与控制

- **服务商限流风险**：单份答卷并发固定上限为 3，全局客户端信号量仍为最终保护层。
- **计算题模型输出变复杂**：采用严格两层校验；旧协议和旧方法完全保留作为回退。
- **低置信度误触发额外成本**：低置信度只进入人工复核，不自动回退；只有结构或映射不可用才回退。
- **跨页映射错绑**：以稳定片段键和模型候选序号绑定，再由本地生成证据 ID；最终仍执行 v1 证据与数据库区域的一致性校验。
- **并发异常留下后台任务**：显式排空/取消子任务，提交仍在全部识别完成之后。
- **覆盖仓库现有修改**：只使用小范围补丁，修改前后检查目标文件差异，不重置或覆盖用户改动。
