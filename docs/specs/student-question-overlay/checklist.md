# 学生试卷整题区域展示与任务删除 Checklist

> **已被部分取代（2026-08-09）：** 本文关于学生侧自动补算/扩张题框、缺页时继续识别、以答案框或外接框代表整题范围的规则，已由 [题框驱动的逐空识别与模型批改 Spec](../2026-08-09-question-frame-blank-grading-pipeline/spec.md) 取代。本文仅保留历史决策记录；新实现必须使用教师确认的完整题框集并对整批映射失败关闭。

> 每项必须通过运行测试、检查接口响应或观察真实页面来验证。实施完成前保持未勾选；验收时记录实际证据后再勾选。

## 模板整题区域

- [ ] 新建任务完成试卷识别后，每道可用题目至少保存一个完整题目区域，区域覆盖题干、全部选项、插图和作答位置，不只是答题框。（验证：检查真实模板识别响应与数据库 `question_regions_json`，对应 AC1）
- [ ] 同一题的多个不连续片段按页面和位置稳定排序，跨页题的每个片段保留正确模板页码和同一题目 ID。（验证：运行跨页/多区域单元测试并检查接口响应，对应 AC2）
- [x] bbox、xywh 和 0～1000 模型坐标都被规范化为 0～1；负面积、非数值、越界和无效页码不会落库。（证据：`test_normalizes_full_question_regions_and_rejects_invalid_geometry`）
- [x] 重叠识别批次合并后不会丢失跨页片段，也不会为同一片段生成重复框。（证据：`test_merges_and_orders_full_question_regions_without_duplicates`）
- [ ] 低置信度或带问题的模板区域保留可读问题并进入“需要检查”，系统不会生成默认猜测框。（验证：使用缺失和低置信度伪模型响应）

## 原页坐标映射与持久化

- [ ] 恒等、平移、缩放和透视变换下，模板矩形的四个顶点按 `template_to_student` 方向映射到学生原页。（验证：运行几何映射单元测试，对应 AC3）
- [ ] 映射结果同时包含学生原页像素四边形和裁剪到页面可见范围的外接框，所有坐标均在对应原页尺寸内。（验证：运行越界和页面边缘测试）
- [x] 学生整题区域引用原始 `student_pages`，不保存裁剪图作为唯一证据，也不改变原始页面文件。（证据：学生流水线测试检查 `student_question_regions.student_page_id`、原页四边形与空裁剪路径）
- [x] 新学生提交成功后，页面、作答记录和整题区域在同一最终事务中可见。（证据：`test_pipeline_keeps_original_page_coordinates_and_transcribes_region`）
- [x] 新学生提交重跑失败或被取消后，上一代页面、作答记录和整题区域仍完整可查询。（证据：同一流水线测试的失败重跑断言）
- [ ] 删除学生页或学生提交时，关联整题区域通过外键级联删除，不遗留孤儿记录。（验证：运行数据库外键检查）

## 历史任务补全

- [x] v4 数据库升级到 v5 后，历史题目区域为空，历史学生提交区域状态为 `pending`，原有题目、作答和原页数据不变。（证据：数据库 v4 重建/迁移保留测试与 v5 幂等测试）
- [ ] 打开历史学生页面后只启动一次任务级区域补全作业；重复请求复用正在运行的作业。（验证：运行补全 API 集成测试和前端请求次数断言，对应 AC4）
- [ ] 历史补全从已保存的空白模板获得整题区域，并使用已保存对齐矩阵映射学生原页，不重新调用学生答案识别。（验证：伪客户端调用记录中没有学生作答识别调用）
- [ ] 历史任务补全完成后刷新页面复用已保存区域，不再次调用模板视觉模型。（验证：连续两次读取/补全并比较模型调用次数）
- [ ] 缺少模板区域或对齐矩阵时，提交显示缺失题目或“需要检查/失败”文字状态，不显示虚假多边形。（验证：运行缺失数据场景并观察接口及页面，对应 AC4、AC6）

## 学生试卷前端

- [ ] 教师可从任务审核页进入学生试卷页面，并看到学生上传入口和提交列表。（验证：从真实路由点击进入，对应 AC5）
- [ ] 上传学生姓名、学号和试卷文件后，列表显示上传、对齐、识别直至完成的状态，处理中自动刷新。（验证：运行页面交互测试，对应 AC6）
- [ ] 处理失败时显示错误原因和重试入口；点击重试只发出一次请求。（验证：模拟失败响应并执行重试，对应 AC6）
- [ ] 学生详情逐页加载受控的原始页面 URL，上一页、下一页和当前页码正确工作。（验证：运行多页 UI 测试）
- [x] SVG 的 `viewBox` 等于学生原页宽高，每个区域使用 API 返回的原页像素顶点绘制，未在浏览器中从答题框推算整题框。（证据：`student-overlay.test.tsx`）
- [ ] 调整浏览器宽度或缩放后，原图与 SVG 共享同一缩放比例，题框仍与题目内容重合。（验证：在 1280×720 和更宽窗口进行视觉检查，对应 AC5）
- [ ] 同一题跨页或多片段时，每个对应页面显示正确片段，并使用同一题号和选中状态。（验证：运行跨页 UI 测试，对应 AC2）
- [x] 点击题框或题号只改变中性选中样式；页面不存在对勾、叉号、“正确/错误”标签或评分颜色。（证据：`student-overlay.test.tsx` 的文本与选中类断言）
- [ ] 区域缺失、对齐质量不足和补全失败都有文字提示，状态不只依赖颜色表达。（验证：逐一模拟三种状态）
- [ ] 在桌面 Chrome 和 Edge 的 1280×720 窗口中，学生列表、原图、翻页、上传和重试控件可达，长页可以滚动。（验证：浏览器手工检查）

## 任务永久删除

- [ ] 每张任务卡具有独立的打开入口和删除按钮，不存在按钮嵌套链接，也不会因点击删除而打开任务。（验证：运行任务列表 UI 测试并检查控制台警告）
- [x] 点击删除后显示任务标题和永久删除范围，包含空白卷、参考答案、学生试卷、识别结果和页面图片。（证据：删除确认组件测试）
- [ ] 在确认对话框选择取消或按 Escape 后，不调用删除接口，任务、文件和学生提交保持不变。（验证：UI 测试断言请求次数为零，对应 AC7）
- [ ] 确认删除期间按钮被禁用，连续点击不会产生重复请求；删除失败时任务仍可见并显示错误。（验证：延迟和失败响应 UI 测试）
- [ ] 删除正在处理的任务时，任务识别、区域补全和该任务所有学生处理作业被精确取消并等待结束。（验证：运行带阻塞伪作业的集成测试，对应 AC8）
- [x] 取消目标任务作业不会停止另一个任务的同类作业，旧作业完成回调不会删除同键的新作业。（证据：两个 JobManager 并发测试）
- [x] 删除成功后，任务从列表消失，任务和学生详情返回未找到，关联数据库记录全部消失。（证据：学生提交 API 集成测试中的永久删除场景）
- [x] 删除成功后，仅目标任务的 `uploads/pages/tmp` 目录被清理；另一个任务及数据根目录外的文件保持不变。（证据：`test_remove_task_files_is_isolated_and_rejects_path_traversal`）
- [ ] 删除不存在的任务返回明确未找到结果；重复删除不会触及其他目录。（验证：连续调用删除接口，对应 AC9）
- [ ] 模拟后台取消或文件清理失败时，接口返回明确失败，不报告 `{deleted: true}`。（验证：注入失败并检查响应，对应 AC9）

- [ ] 场景一：创建并确认一套模板 → 上传固定版式学生试卷 → 等待处理完成 → 打开学生页面 → 逐页看到覆盖完整题目的题框和题号，缩放后仍重合。（验证：真实样本操作和截图记录，对应 AC1、AC3、AC5）
