# 题框变更后单题重新识别 Plan

## 架构概览

新增一个由题框版本约束的“单题重新识别”用例。前端把当前题全部题框草稿与当前题框
修订号一次提交；后端先完成题框校验和保存，捕获保存后的题框集 ID、修订号、内容哈希
与片段清单，再从模板原页裁剪这些片段并调用专用单题视觉识别。模型调用结束后，后端
再次核对捕获的题框版本，只有版本仍为当前版本时才原地更新该题的模型识别字段。

整个过程分成“保存并捕获输入 → 外部模型调用 → 校验并提交结果”三段，不在等待模型时
持有数据库事务。识别失败时，第一段已经保存的题框继续保留，原题内容不变；晚到结果
引用了过期题框时被拒绝，不覆盖教师的后续修改。

## 核心数据结构与接口

### SingleQuestionRerecognitionRequest

- `expectedRevision: number`：客户端看到的当前题框集修订号。
- `regions: QuestionFrameFragment[]`：当前题全部片段，包括尚未单独保存的跨页草稿。

### SingleQuestionRecognitionFragment

- `regionKey`：稳定的片段标识。
- `templatePageId`、`pageNumber`、`sortOrder`：页面和阅读顺序事实。
- `image: bytes`：从模板原图按服务器保存后的归一化题框裁剪得到的临时图像。
- `box`：用于运行记录与二次校验的归一化坐标，不发送无关页面内容。

### SingleQuestionRerecognitionCapture

- `taskId`、`questionId`：本次操作的稳定对象。
- `frameSetId`、`frameSetRevision`、`frameContentHash`：模型调用开始前捕获的题框版本。
- `itemRevision`、`regions`：当前题片段版本与有序片段。
- `runId`：独立的 `single_question_recognition` 运行记录。

### SingleQuestionRerecognitionResult

- `questionId`、`runId`：更新的题目和识别运行。
- `frameSet`：保存题框后的当前题框集，供前端同步修订号和片段。
- `recognizedQuestion`：新的模型原始题目字段。
- `teacherOverridePreserved`：是否保留了现有教师内容覆盖。

### HTTP 接口

`POST /question-frame-sets/{frameSetId}/questions/{questionId}/rerecognize`

请求体为 `SingleQuestionRerecognitionRequest`。成功返回
`SingleQuestionRerecognitionResult`；题框冲突、活动中的学生处理/评分、无效片段、模型零题/
多题、模型错误和晚到结果分别返回稳定错误码。

## 模块设计

### 单题重新识别用例服务

**职责：** 编排题框保存、活动任务检查、运行记录、片段裁剪、模型调用、版本复核、原地
题目更新、下游失效和审计。

**对外接口：** 异步接收题框集 ID、题目 ID、期望修订、片段和操作者，返回完整结果。

**依赖：** 题框服务、数据库、设置、识别服务、Pillow 图像裁剪、现有复核失效逻辑。

关键提交规则：

- 题框保存前检查当前题不是重复题，且没有正在运行的学生处理或评分。
- 复用题框服务的版本、归属和几何校验；已冻结题框按现有规则派生新草稿版本。
- 模型成功后再次核对任务当前题框集、题框集修订、内容哈希和题框项修订。
- 只更新 `questions` 中的模型原始字段与 `source_run_id`，保留题目 ID、排序、
  `teacher_override_json`、现有 `matches.answer_entry_id`、教师直接答案和解析。
- `normalized_number` 按有效题号计算：存在教师题号覆盖时继续使用覆盖题号，否则使用新识别题号。
- 匹配关系不自动重选，仅转为待复核并注明“题目重新识别，原答案关联已保留”。
- 题目和题框项保持待确认；依赖旧题干的当前填空配置只标记为过期并保留历史版本，
  不自动生成或改写逐空配置。
- 当前学生处理结果和批改结果按现有失效机制转为需重新处理，历史记录不删除。

### 识别服务

**职责：** 使用新的单题提示词读取一个或多个按顺序提供的题框裁剪，把跨页片段合并为
唯一一道完整题目。

**对外接口：** `recognize_single_question(question_context, fragments)`，返回规范化的一道题、
原始响应和用量。

**校验：** 输出必须是合法试卷题目结构且恰好一题；来源页只能来自输入片段；题号、题干、
选项、题型、分值、置信度和问题沿用现有题目规范化规则。单题提示词不要求模型重新生成
题框或答题区域，教师保存的题框保持唯一几何事实。

### API 与依赖注入

**职责：** 校验请求模型、取得应用级识别服务和设置，调用单题用例服务并使用统一成功/
错误响应格式。

应用状态显式暴露已经由各流水线共享的识别服务，便于接口复用和测试替换，不重复创建
模型客户端。

### 前端题框编辑器

**职责：** 在现有“保存题框修改”旁提供“保存并重新识别本题”，提交当前全部草稿片段，
显示保存/识别中的状态、成功说明和具体错误。

操作规则：

- 普通保存行为不变，仍不调用模型。
- 重新识别按钮在本地题框存在阻断问题、已有其他题框操作或编辑器禁用时不可用。
- 成功后同步服务器返回的题框版本和片段，再刷新复核数据，使题干编辑器显示新的有效内容。
- 若保留了教师覆盖，成功提示明确说明“模型原始识别已更新，当前仍显示教师修改内容”。
- 失败时保留当前可继续编辑的题框；若属于版本冲突，提示刷新并防止覆盖。

## 模块交互

1. 教师为第 12 题切换到下一页，增加并调整题框片段。
2. 教师点击“保存并重新识别本题”，编辑器提交当前题全部片段及题框修订号。
3. 用例服务检查活动任务和版本，保存题框；若原题框集已冻结则派生当前草稿版本。
4. 服务记录运行并按保存后的页码、片段顺序裁剪模板原图。
5. 识别服务一次读取所有裁剪，将跨页内容输出为唯一一道题。
6. 用例服务重新校验题框版本；版本未变化时，在单个数据库事务中更新当前题、运行记录、
   复核状态、依赖失效状态和审计事件。
7. API 返回新题目摘要和保存后的题框集；前端刷新当前复核页。
8. 教师核对题干与题框，随后分别重新确认本题和本题题框。

若第 5 步失败，运行记录标记失败，步骤 3 保存的题框保留，步骤 6 的题目写入完全不执行。
若第 3 步之后题框又被修改，步骤 6 以版本冲突终止，晚到模型结果只留在失败运行记录中。

## 技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 用户入口 | 显式“保存并重新识别本题” | 避免每次试调题框都产生模型调用，意图清楚 |
| 请求粒度 | 一个接口同时提交草稿题框和重识别意图 | 保证识别使用本次保存后的片段，减少前端请求间竞态 |
| 模型输入 | 只发送有序题框裁剪 | 覆盖跨页内容，同时避免无关整卷进入单题模型 |
| 模型调用次数 | 当前题全部片段一次调用 | 让模型直接理解跨页连续关系，避免前端或字符串规则拼接 |
| 数据更新 | 原地更新现有题目 | 保持题目 ID、排序、答案关联和历史外键稳定 |
| 教师覆盖 | 保留并返回显式提示 | 模型不能静默覆盖教师确认或编辑过的内容 |
| 答案匹配 | 保留关联，仅转待复核 | 不因题干补全意外释放或换绑标准答案 |
| 失败语义 | 题框可已保存，原题内容原子不变 | 教师无需重画；失败模型结果不会产生半更新题目 |
| 并发控制 | 保存前与提交前双重版本校验 | 防止模型等待期间的新题框被晚到结果覆盖 |
| 执行方式 | 请求内异步等待单次模型结果 | 操作只涉及一道题，界面可直接反馈成功/失败；运行表仍保留追踪 |
| 配置处理 | 旧填空配置保留历史但标记过期 | 原题变化后不能继续静默信任旧逐空结构，也不自动猜测新配置 |
