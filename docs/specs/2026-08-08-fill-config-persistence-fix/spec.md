# 派生填空配置与正式批改状态一致性 Spec

> **已被部分取代（2026-08-09）：** 本文中“区域冲突不阻断”“只有总分时自动均分”“开始批改时静默生成或确认配置”等旧规则，已由 [题框驱动的逐空识别与模型批改 Spec](../2026-08-09-question-frame-blank-grading-pipeline/spec.md) 取代。本文仅保留历史记录；新流程要求 B1…Bn 的题面空位、独立锚点、标准答案和显式逐空分值严格一致。

## 背景

评分设置接口会为没有保存空位的填空题返回 `derived` 预览，教师因此能看到完整的 B1、B2……答案和分值；但该预览不写数据库。题目确认和任务完成目前也不校验或保存这些空位，直到创建评分运行时才因数据库没有空位记录而统一报“填空题必须配置每个空”。这使界面显示、任务完成状态和正式批改门禁相互矛盾。

当前运行库已复现：第 9、10、11、12 题均已确认且任务已完成，界面可派生多空预览，但四题 `config_version` 均为空、保存空位数均为 0；审计记录没有对应的填空配置保存事件。

## 目标

- 让安全、完整的派生填空配置在教师执行明确确认动作时成为正式保存配置。
- 让题目确认、任务完成和评分启动使用同一套配置就绪判定，避免前一步成功、后一步才出现笼统错误。
- 兼容已经完成但没有保存填空配置的历史任务，使其在重试评分时可安全补齐，不要求逐题重新打开。
- 对无法安全拆分或缺少逐空答案的题目继续阻断，并准确指出题号和原因。

## 功能需求

- **F1：统一配置就绪判定**：系统应以同一规则判断填空配置是否可正式使用：已有保存空位直接通过；否则派生结果必须空位数大于零、每空均有非空标准答案、每空分值有效且总和等于题目满分。
- **F2：明确动作自动确认安全配置**：教师确认题目、完成任务或启动评分时，如果填空题没有保存配置但派生结果满足 F1，系统应保存该配置并记录审计事件。普通 GET 仍保持只读。
- **F3：历史任务评分前补齐**：对于此前已经确认或完成的任务，评分预检应使用 F1 检查缺失配置；全部安全时先幂等保存，再构建本次评分输入，使当前历史任务重试即可继续。
- **F4：歧义配置精确阻断**：派生结果存在空答案、无效分值或其他需要人工检查的警告时，不得自动保存或进入评分；错误应包含题目 ID、题号、预期空位数和稳定原因代码，不再只返回无法定位题目的笼统提示。
- **F5：任务完成门禁一致**：任务完成前应检查所有有效填空题。所有缺失配置均可安全派生时在同一事务中保存并完成任务；任何一题不安全时任务保持未完成，且不会对本次批量候选产生部分保存。
- **F6：界面状态反馈**：评分设置面板应说明安全派生配置会在确认题目、完成任务或启动评分时自动保存；自动保存后重新读取显示 `source=saved`。阻断错误应引导教师回到对应题目的逐空设置。

## 非功能需求

- **N1：幂等与并发安全**：同一题被重复确认、重复完成任务或重复启动评分时最多保留一套当前空位配置，不重复增加版本或审计事件；并发写入不得形成部分空位。
- **N2：数据保护**：已有保存配置始终优先，自动确认不得覆盖教师保存的空位、分值、答案类型、标准答案、同义答案或区域。
- **N3：事务一致性**：自动确认配置与触发它的题目确认、任务完成或评分预检必须具有明确事务边界；失败时不得留下只有配置头或部分空位的状态。
- **N4：无新增模型调用**：自动确认只复用现有确定性初始化规则，不调用模型、不联网搜索答案。
- **N5：可追踪性**：自动确认审计应记录题目、触发动作、空位数量及初始化信号，并能与教师手动保存区分。

## 本轮不做的事情

- 不自动保存包含空标准答案、分值不守恒或需要人工确定答案边界的配置。
- 不让普通评分配置 GET 产生数据库写入。
- 不覆盖任何已有教师保存配置，也不重写历史评分运行快照。
- 不通过模型补答案、拆答案或判断有歧义的空位。
- 不直接修改当前运行库来绕过应用逻辑；历史数据通过修复后的正常确认或评分预检流程补齐。

## 验收标准

- **AC1（F1、F2）**：未保存但可安全派生的三空题在确认后生成一套保存配置和三个空位，再次 GET 返回 `source=saved`；确认前连续 GET 仍不写数据库。
- **AC2（F3）**：构造一个已完成、填空配置为空但三空答案可安全派生的历史任务，创建评分运行时自动保存配置并成功进入评分，不再返回 `FILL_BLANK_CONFIG_REQUIRED`。
- **AC3（F4）**：三空题只能安全确定数量、无法安全分配答案时，确认、完成任务和评分启动均不自动保存，错误详情包含题号、预期三空及 `answer_split_ambiguous`。
- **AC4（F5、N3）**：任务包含两道安全填空题和一道歧义填空题时完成失败，三道本次候选均不产生部分自动保存；修正歧义题后再次完成，三题配置与任务状态在同一事务中提交。
- **AC5（N1、N2、N5）**：重复执行确认、完成或评分预检不会新增重复空位、无意义版本或重复自动确认审计；已有教师配置在所有触发动作后保持逐字段不变。
- **AC6（F6）**：前端显示自动确认说明；后端返回阻断详情时，页面显示具体题号和“逐空检查并保存”，不再只显示无法定位的通用提示。
- **AC7（N4）**：上述确认、完成和评分预检流程的模型客户端调用次数均为 0，完整后端与前端测试、类型检查、静态检查和生产构建无回归。
