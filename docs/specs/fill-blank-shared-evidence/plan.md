# 多填空共享证据与教师审核优先 Plan

## 架构概览

保留已经完成的多填空共享证据能力，在教师复核与报告生成之间增加一条可追溯的“教师裁决”链路。

教师提交确认或改判后，复核服务先生成候选结果并执行现有评分审计。审计发现的证据缺失、位置不确定、分项合计不一致、依赖关系矛盾及其他评分问题全部转为教师裁决的附带告警：保存但不拦截。

复核成功后，题目结果会追加结构化教师裁决记录。最后一个复核项关闭后，现有 API 自动启动报告生成任务。报告服务在存在对应教师裁决记录时允许“低分但无可靠错误位置”的题目降级生成；批注不画虚假红圈，错题报告显示教师复核说明。

## 核心策略与数据结构

### 教师裁决优先策略

评分审计继续返回完整 `AuditIssue` 列表，但复核服务不再根据任何 `ReviewReason` 拒绝教师提交。所有原因统一写入教师裁决记录的 `overriddenReasons` 和 `auditWarnings`。

请求是否可执行在进入评分审计前判断。仅以下情况返回接口错误：复核项不存在、复核项已处理、请求格式不合法、改判没有修改内容、覆盖键在当前题目中不存在，或数据库事务无法完成。这些属于请求/运行错误，不属于评分审计告警。

### 教师裁决记录

复用 `grading_question_results.tool_observations_json`，不新增数据库表或迁移。每次成功复核向现有列表追加一条记录：

```json
{
  "tool": "teacher_review",
  "status": "confirmed",
  "detail": "已查看学生原图，确认本题判定",
  "payload": {
    "reviewItemId": "...",
    "reviewReason": "MISSING_EVIDENCE",
    "overriddenReasons": ["MISSING_EVIDENCE", "SCORE_INCONSISTENCY"],
    "auditWarnings": [
      {"reason": "MISSING_EVIDENCE", "detail": "B2 得分但缺少证据"},
      {"reason": "SCORE_INCONSISTENCY", "detail": "分项得分之和与题目得分不一致"}
    ]
  },
  "tool_version": "teacher-authority-v1"
}
```

改判时 `status` 使用 `overridden`。原有 `grading_review_items.resolution_json` 和 `grading_events` 继续保留请求原文，并同步写入被覆盖原因，形成题目结果、复核项、事件三处一致的审计信息。

### 报告降级判定

报告服务新增只读判断：

```python
has_teacher_review(result) -> bool
```

只有同时满足以下条件才允许无错误位置生成：

1. 题目状态为最终状态；
2. 全卷没有待复核项；
3. 题目存在有效教师裁决记录。

否则继续返回现有 `ANNOTATION_ERROR_LOCATION_REQUIRED`，防止没有教师参与的自动批改结果绕过完整性要求。

## 模块设计

### 评分审计模块

**文件：** `backend/homework_judge/grading/audit.py`

**职责：**

- 保持 `audit_question`、`audit_exam` 返回完整评分审计结果。
- 提供教师裁决记录的读取函数，供报告生成判断该题是否已经人工审核。
- 修正依赖矛盾检查的执行位置，使其不依赖“是否缺少错误位置”，保证告警始终被完整记录。
- 保持自动批改阶段的严格行为不变；仅教师提交阶段把审计结果降级为记录。

### 教师复核模块

**文件：** `backend/homework_judge/grading/review.py`

**处理顺序：**

1. 读取当前复核项、题目结果及历史教师裁决。
2. 填空题先执行已有共享证据补齐。
3. 应用教师确认或改判。
4. 构造最终候选结果并执行完整审计。
5. 把全部审计问题作为告警追加到教师裁决记录，不再抛出评分矛盾错误。
6. 在同一事务中关闭当前复核项、更新题目结果和评分明细。
7. 查询同题剩余复核项：有剩余则保持 `needs_review`，无剩余才标记 `final`。
8. 刷新整卷待复核数量与结果版本；归零时进入 `generating_annotation`。

数据库更新补齐 `tool_observations_json` 字段。原有状态条件更新继续保证同一复核项不会被重复关闭。

### 复核 API 与后台任务

**文件：** `backend/homework_judge/api/grading.py`

沿用现有“复核成功后重新读取运行状态”的行为。最后一项复核使运行进入 `generating_annotation` 后，以当前结果版本启动唯一的报告生成任务。

必要时只补充返回字段或日志，不改变前端提交协议，避免破坏已有页面。

### 批注与错题报告

**文件：**

- `backend/homework_judge/artifacts/service.py`
- `backend/homework_judge/artifacts/annotation_layout.py`
- `backend/homework_judge/artifacts/error_report.py`

**职责：**

- 报告服务读取题目教师裁决记录。
- 普通低分题缺少错误位置时继续失败。
- 题目存在有效教师裁决记录时，不再因无错误位置抛出冲突；批注布局沿用现有无位置即不生成错误标记的行为。
- 错题报告仍收录该题，并把教师复核说明加入错误原因文字；没有区域时不生成证据截图。
- 报告完成后运行状态正常进入 `completed`，批注 PDF 和错题报告 PDF 均记录为当前版本。

### 前端复核反馈

**文件：** `client/src/features/grading/GradingWorkspacePage.tsx`

页面沿用现有加载禁用、成功提示和失败提示。验证教师确认成功后自动跳到下一复核项；最后一项完成后显示“正在生成结果文件”，并由轮询状态呈现最终报告。若实际验证发现状态切换存在空窗，再做最小调整，不改变教师操作方式。

## 模块交互

```text
教师点击确认/改判
  → 应用教师结论
  → 执行完整评分审计
  → 记录全部评分审计告警（不拦截）
  → 关闭当前复核项
  → 同题仍有复核项？──是──→ 保持待复核并定位下一项
  │
  否
  → 题目最终化
  → 全卷仍有复核项？──是──→ 继续复核
  │
  否
  → 自动生成批注与错题报告
  → 无错误位置且有教师裁决：不画红圈，保留文字说明
  → 运行完成
```

## 技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 教师优先边界 | 教师明确提交后覆盖全部评分审计告警 | 教师审核是业务最终结论，审计只负责提示与追溯 |
| 审计记录载体 | 复用 `ToolObservation` 并同步复核事件 | 无需迁移数据库，题目结果和历史事件均可追溯 |
| 报告放行条件 | 必须存在有效教师裁决记录 | 防止没有人工审核的无位置题被静默放行 |
| 无位置批注 | 不绘制错误圈，不伪造区域 | 如实表达系统没有可靠坐标 |
| 无位置错题报告 | 保留题目文字与教师说明，省略截图 | 保证报告完整生成，又不误导学生 |
| 多复核项状态 | 一项一项关闭，最后一项才最终化题目 | 避免确认一个原因时误关其他风险项 |
| 自动生成触发 | 复用现有运行状态与唯一后台任务键 | 保持接口行为兼容并避免重复生成 |
| 历史运行兼容 | 提交复核时即时应用新策略 | 当前答卷无需重新识别、重新评分或迁移数据 |

## 验证策略

1. 单元测试验证完整告警收集、教师裁决序列化、重复提交和依赖矛盾记录。
2. 服务测试覆盖当前第 9 题形态、低分无错误位置、多原因逐项关闭，以及分项合计/依赖矛盾不拦截。
3. 报告测试验证有教师裁决时无红圈但有错题文字，无裁决时仍返回原错误。
4. API 集成测试完成“最后一项复核 → 自动生成 → 两份产物当前有效”的完整链路。
5. UI 测试验证按钮加载禁用、成功定位下一项、失败提示和最后一项后的生成提示。
6. 运行后端完整测试、静态检查、类型检查、前端测试与生产构建。
7. 使用隔离测试数据复现教师确认；不代替用户提交真实答卷的复核决定。
8. 验证通过后重启当前本地后端服务，再从浏览器复核接口确认新逻辑已生效。
